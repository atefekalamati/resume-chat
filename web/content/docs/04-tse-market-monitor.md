# پایش بازار بورس تهران — انبار داده و داشبورد

## خلاصه
**فارسی:** یک انبار دادهٔ کامل روی SQL Server برای همهٔ نمادهای بورس و فرابورس تهران. داده با Python جمع‌آوری می‌شود، با رویه‌های ذخیره‌شده و MERGE بارگذاری افزایشی می‌شود، هر روز کاری خودکار اجرا می‌شود و در یک داشبورد ۶ صفحه‌ای Power BI نمایش داده می‌شود.

**English:** A production-style SQL Server data warehouse for all 747 Tehran Stock Exchange and Fara Bourse symbols: Python ingestion, staging→DW layers, star schema with an SCD2 symbol dimension, idempotent MERGE loads, row-level reconciliation, scheduled daily runs, 28 validated T-SQL queries, and a 6-page Power BI dashboard.

## مسئله و هدف
- ساخت زیرساختی تکرارپذیر و قابل‌اعتماد برای دادهٔ روزانهٔ بازار، نه یک تحلیل یک‌باره.
- پاسخ به این پرسش‌ها:
  - رشد بازار به ریال و به دلار چقدر بود؟
  - رشد گسترده بود یا متکی به چند نماد بزرگ؟
  - رفتار پول حقیقی چه رابطه‌ای با بازده دارد؟

## داده
| مورد | مقدار |
|---|---|
| منبع | TSETMC |
| پوشش | ۷۴۷ نماد بورس و فرابورس، ۴۵ شاخص صنعت، نرخ دلار |
| بازه | ۱۴۰۲/۰۱/۰۱ تا ۱۴۰۵/۰۸/۱۶ |
| حجم | حدود ۴۶۰ هزار ردیف قیمت و ۴۳۳ هزار ردیف حقیقی/حقوقی |

## معماری
- **لایه‌ها:**
  - `staging`: دادهٔ خام.
  - `dw`: مدل ستاره‌ای.
  - `etl`: لاگ و کنترل اجرا.
- **مدل ستاره‌ای:**
  - ۴ بعد؛ بعد نماد (DimSymbol) از نوع **SCD Type 2** است تا تغییر نام یا صنعت نماد با تاریخچه حفظ شود.
  - ۵ جدول واقعیت.
- **بارگذاری:**
  - رویه‌های ذخیره‌شده با **MERGE** و واترمارک برای بار افزایشی.
  - **Idempotent**: اجرای اول ۹۳۶٬۶۴۹ ردیف درج کرد؛ اجرای دوم روی همان داده ۰ ردیف تغییر داد.
- **تطبیق (Reconciliation):** جمع ارزش معاملات منبع و انبار مقایسه شد. اختلاف صفر بود؛ جمع کل ۶۶٬۰۱۳٬۹۵۶٬۵۶۴٬۹۲۵٬۷۳۶ ریال.
- **زمان‌بندی:** اجرای خودکار شنبه تا چهارشنبه ساعت ۱۶:۰۰ با Windows Task Scheduler. نسخهٔ Express، SQL Agent ندارد؛ اسکریپت معادل SQL Agent هم آماده است.

## کیفیت داده
- ۱۸۷ خطای مقیاس قیمت پیدا و اصلاح شد.
- ۹۴ روز اولِ درج نماد شناسایی شد تا بازده کاذب نسازد.

## SQL و بهینه‌سازی
- ۱۲ کوئری تحلیلی و ۱۶ تمرین T-SQL؛ هر ۲۸ مورد روی داده اجرا و تأیید شد.
- مفاهیم: توابع پنجره‌ای، CTE، رتبه‌بندی، میانگین متحرک.
- **تنظیم ایندکس:** خواندن منطقی یک کوئری با یک ایندکس مناسب از ۱۱٬۴۶۴ به ۶۴ رسید.

## داشبورد
- Power BI در ۶ صفحه با ۴۳ معیار DAX.
- ۱۱۲ از ۱۱۲ بررسی عددی درست بود.
- ۷۸ تست خودکار برای کل پروژه.

## نتایج کلیدی
- **ریال در برابر دلار:** شاخص کل به ریال ۳۰۴٫۵٪ رشد کرد، اما به دلار حدود ۲۳٪ افت داشت.
- **کیفیت رشد:**
  - رشد ۱۴۰۳ متکی به نمادهای بزرگ بود.
  - رشد ۱۴۰۵ گسترده‌تر بود و نمادهای بیشتری با هم رشد کردند.
- **پول حقیقی:**
  - ورود پول حقیقی با بازده همان روز همبستگی ۰٫۶۸۵ دارد.
  - همبستگی آن با بازده روز بعد فقط ۰٫۲۸۳ است؛ پول حقیقی دنبال‌کنندهٔ بازار است، نه پیش‌بینی‌کننده.
- **بعد از تعطیلی بازار:** شاخص در ۲۰ روز ۳۷٫۳٪ بالا رفت و ارزش معاملات روزانه دو برابر شد.

## محدودیت‌ها
- منبع داده فقط از IP داخل ایران در دسترس است.
- نسخهٔ Express، SQL Agent ندارد.
- تحلیل‌ها توصیفی‌اند و توصیهٔ سرمایه‌گذاری نیستند.

## مهارت‌هایی که نشان می‌دهد
طراحی انبار داده، SCD2، بار افزایشی و Idempotent با MERGE، تطبیق داده، زمان‌بندی Job، T-SQL پیشرفته، بهینه‌سازی با ایندکس، DAX، تست و مستندسازی کامل.

## سؤال‌های متداول (برای چت‌بات)
**فرق این پروژه با پروژهٔ تورم چیست؟**
آن پروژه یک تحلیل بود. این یکی زیرساخت دادهٔ روزانه است: انبار داده، ETL خودکار، کوئری و داشبورد.

**SCD Type 2 چیست؟**
روشی که وقتی ویژگی یک نماد (مثل صنعت) عوض می‌شود، ردیف قبلی با تاریخ اعتبار نگه داشته و ردیف جدید اضافه می‌شود تا تاریخچه از بین نرود.

**Idempotent یعنی چه؟**
اجرای دوبارهٔ بارگذاری روی همان داده چیزی را تکراری یا خراب نمی‌کند. در این پروژه اجرای دوم ۰ تغییر داشت.

**از کجا مطمئن شدید داده درست است؟**
با تطبیق جمع ارزش معاملات منبع و انبار (اختلاف صفر)، ۱۱۲ بررسی عددی داشبورد و ۷۸ تست.

**مهم‌ترین یافته؟**
شاخص کل به ریال ۳۰۴٪ رشد کرد، ولی به دلار حدود ۲۳٪ افت داشت.
